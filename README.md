# 学习通挂答一体化工具（骨架说明）

> 本仓库只包含两样东西：**这份说明** 和 **脱敏后的主引擎脚本 `scripts/required_walker.py`**。
> 引擎不内置任何账号、课程编号、平台域名或本机路径——这些全部放在工作目录（不入库），
> 由脚本运行时读取。

## 1. 这个工具能做什么

面向「超星学习通 / 慕课平台」网页版课程的**自动化学习脚本骨架**，主要能力：

| 能力 | 说明 |
| --- | --- |
| 章节顺序遍历 | 按预设的叶子小节清单逐节推进，已完成的自动跳过 |
| 视频任务点 | 无头浏览器打开播放页，自动播放至结束，支持倍速 |
| 文档任务点 | 通过平台文档任务点接口自动标记完成 |
| 章节测验 | 拉到题目后写出待答文件，外部给出答案后自动勾选/填写作答并提交 |
| 字体加密题 | 平台用自定义字体混淆题干与选项，脚本渲染「序号-汉字」对照表，供外部解码还原明文 |
| 断点续跑 | 进度写入状态文件，进程中断后重启会从下一个未完成小节继续 |
| 异常自愈 | 网络抖动退出可重启续跑；「上一节已通过但未解锁」会重载核对，必要时重播未登记的视频 |

整个流程**无前台窗口**，可后台常驻运行。

## 2. 需要自己准备哪些信息（以及放在哪）

引擎通过 `--workdir`（或环境变量 `XXW_WORKDIR`）指向工作目录 `WORKDIR`，运行前需在其中准备：

```
WORKDIR/
├── cookies.txt             # 登录后的浏览器 Cookie（Netscape 格式或 name=value 串）【必填】
├── course_config.json      # 课程上下文【必填】
├── required_leaves.json    # 要遍历的小节清单 [{"id": "<知识点id>", "name": "<小节名>"}]【必填】
├── required_state.json     # 进度状态（可不存在，首次运行会新建）
├── font_map.json           # 可选：历史字体映射（码点十进制 -> 汉字），用于解码旧题
├── pending_quiz.json       # 运行中生成：当前待答题目
├── font_grid_pending.html/.png  # 运行中生成：字体对照表
└── quiz_answers.json       # 由外部写入：答案文件
```

**放入方式**

1. `cookies.txt`：浏览器登录后用插件导出，存为文本即可。
2. `course_config.json`：从课程页面地址栏取编号、从站点地址取域名，写成 JSON（值替换成你自己的）：
   ```json
   {
     "courseId": 0,
     "clazzId": 0,
     "domain": "你的慕课平台域名",
     "cpi": 0,
     "cookie_domains": [".你的平台域名"]
   }
   ```
   - `courseId` / `clazzId` / `domain` 必填；`cpi`、`cookie_domains` 可选（Cookie 域缺省为 `[".chaoxing.com"]`）。
   - 缺少这三项时脚本会直接报错退出，不会带任何默认值。
3. `required_leaves.json`：按章节树整理知识点 id 与名称，顺序即执行顺序。
4. 其余文件不用手工创建。

> 上述文件都属于个人信息/课程数据，**只能放在本机工作目录**，不要提交到任何仓库或分享出去。

## 3. 如何使用

```powershell
python scripts/required_walker.py --workdir "<WORKDIR>" --rate 2 --quiz-wait-min 90
```

`--workdir` 必填（或设置环境变量 `XXW_WORKDIR`）；无头浏览器路径可用环境变量 `XXW_CHROME` 覆盖（默认系统 Chrome）。

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--workdir` | 工作目录（放上面那些输入文件的地方），必填 |
| `--rate` | 视频播放倍速，默认 2 |
| `--quiz-wait-min` | 出题后等待答案文件的最长分钟数 |
| `--no-recheck-prev` | 未解锁时不回看上一节页面（避免重复访问旧内容） |
| `--max-leaves` | 最多处理多少个小节，便于小步试跑 |

运行日志与进度都在 `WORKDIR` 内（`required_watch.log`、`required_state.json`）。

## 4. 答题环节需要人工 / AI 介入（重要）

**引擎不会自动产生答案。** 它只负责播放、提取题目、提交与判分反馈；「给出正确答案」这一步必须由外部作答者（你自己，或 AI）完成。

### 4.1 分工边界

| 环节 | 引擎自动 | 需要人/AI |
| --- | --- | --- |
| 播放视频 / 完成文档点 | ✔ | |
| 提取题目、渲染字体对照表 | ✔ | |
| 还原加密题干明文 | | ✔ 读对照表认字（首次每课都要做一次） |
| **给出答案** | ✘ | ✔ 按题意语义判断（无题库可查，平台不暴露答案） |
| 勾选 / 填写 / 提交 | ✔ | |
| 读判分反馈（stuStatus 或错题标记） | ✔ | |
| 根据反馈修正答案并重做 | | ✔ 定位错题、改答案；移出完成清单的操作见 §4.4 |

说明：

- **没有题库检索、没有答案接口。** 平台判分只给出对/错/半对，不告知正确答案，因此答案是「作答者判断 + 判分反馈纠错」的收敛过程。
- 同一知识点重做时 qid 会变，不能按 qid 缓存答案；要缓存请用**题干规范化文本的哈希**做键。
- 判断题/常识题（如安全常识）不解码也能答；语义靠积累的字体映射（`font_map.json`）可以让题干可读，但「读题后选哪个」仍需人/AI 判断。

### 4.2 问题文件格式：pending_quiz.json（引擎生成，供作答者阅读）

```json
{
  "kid": "<知识点id，节标识，仅供追踪>",
  "name": "<小节名称>",
  "num": 1,
  "questions": [
    {
      "idx": 0,
      "type": "【单选题】",            <!-- 【单选题】【多选题】【判断题】【填空题】等 -->
      "stem": "<题干（若字体已映射则已还原成明文）>",
      "opts": [
        { "qid": "<题id，作答时的键>", "qtype": "0",    <!-- 0单选 1多选 2填空 3判断 -->
        "data": "A", "label": "A", "text": "<选项内容>" }
      ]
    }
  ]
}
```

字段说明：

- `stem`：题干；若该课字体映射已积累，此处已是可读明文，否则部分字符为密文，需配合 §4.3 解码。
- `opts[].qid`：题的唯一 id，是答案文件的键；把答案写到对应的 qid 下。
- `opts[].qtype`：题型（同一题的所有选项共享同一 qid）。
- `opts[].data/label`：选项字母（单选/判断）；多选/填空为空。
- `opts[].text`：选项内容或（判断题）「对/错」。

### 4.3 被字体混淆的题目如何读

1. 打开 `font_grid_pending.png`（无头渲染的对照表，每格：上方红色序号、下方真实汉字）。
2. 把 `font_grid_pending.html` 里的「序号 → 密文字符」顺序与图对照，得到密文→明文映射。
3. 结果可回写 `font_map.json`（码点十进制 → 汉字），后续同类题自动解码：
   ```json
   { "21700": "要", "21723": "题", "21729": "和" }
   ```

形近字建议逐行放大复核；识别错误会导致整题答错（平台会判错但不会告知正确答案）。

### 4.4 答案文件格式：quiz_answers.json（作答者写入，键为 qid）

```json
{
  "<qid>": [ "<answer>" ],
  "<qid>": [ "<answer>" ]
}
```

三种取值写法（与引擎 apply_answers / fill_blanks 对应）：

| 题型 | answer 写法 | 示例 |
| --- | --- | --- |
| 单选 / 判断 | 选项字母（label） | `["A"]`、判断题对=`["A"]` 错=`["B"]` |
| 多选 | `opt:<索引>`，索引从 0 开始 | `["opt:0", "opt:2", "opt:3"]` |
| 填空 | `txt:<文本>` | `["txt:根部"]` |

完整示例：

```json
{
  "405806947": ["A"],
  "405801001": ["opt:0", "opt:1", "opt:2", "opt:4"],
  "405801002": ["txt:根部"],
  "405800568": ["C"],
  "405800569": ["B"]
}
```

要点：

- 文件写入后，脚本会自动清空旧内容再读取，无需重启。
- 只需写入待答的 qid，其他 qid 留空不会影响。
- 未达线（`stuStatus=5`）时不会自动重做，需要：定位错题（提交页的 marking 标记或日志）→ 修改对应 qid 的答案 → 把该小节从 `required_state.json` 的 `doneLeaves` 中移除 → 再次启动脚本（脚本会自动重做该节）。
